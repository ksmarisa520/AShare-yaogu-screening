# backtest/

两个可执行性回测。它们回答的不是"能不能涨"，而是**"这套东西扣掉成本之后，还能不能赚到钱"** —— 这个问题用日线数据能回答到什么程度，就是这里的上限。

```
backtest/
├── zt_backtest.py   涨停侧：打板能不能成交、成交了赚不赚  → docs/03_forward_backtest_2026-10.md
└── dt_backtest.py   跌停侧：抄跌停、次日低开做日内能不能做 → docs/04_reverse_backtest_2026-10.md
```

```bash
python3 backtest/zt_backtest.py
python3 backtest/dt_backtest.py

python3 backtest/zt_backtest.py --cost 0.004      # 成本敏感性
python3 backtest/dt_backtest.py --cost 0.001 --slip 0.001 --maxfb 0.05
```

零依赖，纯标准库。读的是 `data/` 里的**冻结快照**（固定用仓库内的数据，不读用户缓存），所以任何人在任何时间跑，结果都和文档逐格一致。

## 一句话结论

| 方向 | 最好的那条路径 | 结论 |
|---|---|---|
| 正向（涨停） | 打板 → 次日开盘卖 | **−0.06%/笔**，日聚合 t=−0.65。溢价全锁在买不到的那一侧 |
| 反向（跌停） | 次日开盘买 → 当日收盘卖 | **+1.03%/笔**，但 0.4% 成本下 t 掉到 1.50；只有恐慌日子集 t=3.06 |

**正向被可成交性锁死，反向被方向锁死。**

## 数据

| 文件 | 内容 |
|---|---|
| `zt_study.json` | 涨停池 / 炸板池 / 跌停池快照（15 个有数据的交易日） |
| `zt_kl.json` | 涨停池涉及个股的日 K（含开盘价） |
| `dt_pools.json` | 跌停池快照（15 个跌停日） |
| `kl_store.json` | 跌停池涉及个股的日 K |
| `bench.json` / `bench_oc.json` | 国证2000、中证全指日线；后者含开盘价，用于算日内超额 |
| `zt_obs.json` | 693 条「涨停股-日」明细（`zt_backtest.py` 的产物，已固化） |
| `dt_obs.json` | 219 条「跌停股-日」明细（`dt_backtest.py` 的统计基础） |

## 三条必须一起读的限制

1. **样本只有 14 个交易日。** 693 / 219 笔在统计上只等于 14 个独立观测，所以全部按交易日聚合做 t 检验，不按笔数。
2. **只有日线，没有盘口。** 打板成败真正取决于封单量随时间的衰减和撤单率，日线看不到。所以正向回测只能算到"能不能成交"这一层，再往下算不了。
3. **窗口是下跌市。** 国证2000 −11.76%、中证全指 −10.80%。小盘被系统性惩罚，换一个风格窗口，分档结论可能反过来。

## 一条方法论红线

跌停侧 S3 如果把"次日收盘封死跌停、根本卖不掉"的样本剔掉，胜率会从 52.1% 变成 62.3%、均值从 +1.03% 变成 +2.15%。**这个数字不能用**——买的时候不可能知道明天卖不卖得掉，剔除等于事后挑样本。凡是这类"事后可知"的过滤，都只能当诊断，不能当业绩。
