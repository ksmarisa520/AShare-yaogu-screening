# data/

冻结的研究快照。**只读**——脚本的所有写入都进 `~/.cache/yaogu/`，不会碰这里。

## 池子与行情

| 文件 | 说明 |
|---|---|
| `zt_study.json` | 东财涨停池 / 炸板池 / 跌停池原始缓存，`{"YYYYMMDD": {"zt": [...], "zb": [...], "dt": [...]}}`。96 个交易日 key（2026-06-01 → 2026-10-21），**其中 15 天有数据**（2026-09-23 起）。其余 81 天是全空占位，印证「东财池子 API 只保留最近约 1 个月」。注：这份快照的 `dt` 数组是空的——抓的时候还没发现跌停池要 `sort=fund:asc`，跌停数据单独放在 `dt_pools.json`。 |
| `dt_pools.json` | 跌停池快照，15 个跌停日，用正确排序字段抓的。`scripts/base_rates.py` 会自动合并进 `dt` 层（TABLE 1.5 次日跌停率的数据来源） |
| `zt_kl.json` | 涨停池涉及个股的日 K（含开盘价），回测正向用 |
| `kl_store.json` | 跌停池涉及个股的日 K，回测反向用 |
| `bench.json` | 国证2000 / 中证全指 日收盘 |
| `bench_oc.json` | 同上，含开盘价——算「日内超额」必须用这个 |
| `daily_limitup_summary.csv` | 逐日涨停 / 炸板 / 跌停家数摘要，15 行。最后一行 2026-10-21 是盘中快照，做统计要剔除（`base_rates.py` 已内置） |

## 明细（回测产物，已固化）

| 文件 | 说明 |
|---|---|
| `zt_obs.json` | 693 条「涨停股-日」：开/收/隔夜/日内/板块梯队/炸板次数/封单比/连板数/超额 |
| `dt_obs.json` | 219 条「跌停股-日」：开/收/隔夜/日内/超额/是否跌停/是否买不到 |

这两份不是输入，是 `backtest/` 跑出来的结果，留着当证据。重跑会写到 `~/.cache/yaogu/` 下的副本，不影响这里。

## 为什么只读

`zt_study.json` 里 2026-09-23 → 10-21 这段历史已经超出东财 API 的约 1 个月保留期，**现在重新抓只会拿到空数组**。它是这段样本的唯一副本，覆盖了就永久丢失。

## 复现文档里的表

```bash
# 基准率表（14 天窗口，逐格一致）
python3 scripts/base_rates.py --offline

# 双向回测
python3 backtest/zt_backtest.py
python3 backtest/dt_backtest.py
```

回测脚本固定读本目录（`read_fixture`），不读用户缓存，所以无论你本地积累了多少新数据，结果都不变。
